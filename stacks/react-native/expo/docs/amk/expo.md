# Expo rules

Rules for things AI agents commonly get wrong in Expo apps. Each one comes from a documented platform change, or from a bug agents keep making on screens. `node scripts/amk/rn-check.js`, which `verify.sh quick` runs, checks the lines a branch changes for some of them.

## Expo changes with every SDK

- Expo APIs are renamed and moved between SDKs, so don't write them from memory. Use the docs for this app's SDK (the version is in `AGENTS.md`): `https://docs.expo.dev/versions/v<SDK>.0.0/`. `https://docs.expo.dev/llms.txt` indexes all of Expo's docs.
- Add libraries with `npx expo install <package>`: it picks the version that matches the SDK. `npx expo install --check` lists the ones that don't match.
- Upgrade the SDK as a whole with the `expo-upgrade` skill, never one Expo package at a time.
- Without an ESLint config (`eslint.config.js`), the first `npx expo lint` installs ESLint and writes one, changing `package.json`. Ask before running it then.

## Native projects

- `ios/` and `android/` are generated by `npx expo prebuild` and aren't in git. Never edit them: the next prebuild overwrites the change.
- Native settings (permissions and their texts, bundle ID, entitlements) go in `app.json` or `app.config.*`. Libraries with native setup bring a config plugin; add it to `plugins`.
- Native code of the app's own goes in an Expo module (`expo-module` skill), not into the generated folders.
- Run the app in a development build, not Expo Go: Expo Go can't load native code the app adds, and the store version runs only one SDK. `sh scripts/amk/verify.sh` makes release builds with the current native code.
- Android release builds shrink the code with R8 (on by default from SDK 58). A crash only in release builds usually means a missing keep rule: add the rule; don't turn R8 off.

## Architecture

- React Native 0.82 and later run only the New Architecture, and so does Expo. Libraries must support it.

## Screens and layout

- Use Expo Router for navigation (`expo-router` skill). Every file in the routes folder is a screen; keep components, hooks and utilities outside it.
- Use `react-native-safe-area-context` for safe areas. React Native's built-in `SafeAreaView` is deprecated and iOS-only.
- Android draws edge to edge (Android 15 and later), so handle top and bottom insets on every screen.
- For apps targeting Android 16 (API 36), `onBackPressed` is no longer called. Handle back with `BackHandler` in JS.
- With the keyboard open, the field being typed in and the button that submits the form stay visible and tappable, on both platforms.
- New screens use the app's design system (`docs/amk/design-system.md`): its colours, type sizes, spacing, radius and shared controls. Something it doesn't have (a colour, a component) goes into it and the theme first, not into one screen.
- Every field has a visible label; a placeholder only shows the format (`DD/MM/YYYY`), never the label, which disappears once the user types.
- The keyboard and autofill fit the field: `keyboardType` (`email-address`, `number-pad`, `phone-pad`), `autoComplete` (`email`, `password`, `one-time-code`, `postal-code`, …) and on iOS `textContentType`, `autoCapitalize="none"` for emails and codes, `secureTextEntry` for passwords, and `returnKeyType` with `onSubmitEditing` going to the next field.
- A field is checked when the user leaves it, then as they type; its error shows under it and says what to do. The submit button is disabled only while the request runs.
- A button that starts a request shows it's working without changing size, ignores a second tap until the request ends, then shows the result or the error: never a success message when nothing was saved. A destructive action asks first, or can be undone.
- Lists that grow with the user's data scroll (`FlatList`, or the list component the app already uses), and so does any screen taller than a small phone.
- At the largest system text size, text wraps instead of being cut off: no fixed heights on views that hold text. Don't turn off font scaling (`allowFontScaling={false}`) to make a layout fit.
- Messages that appear after an action, such as a form error, are read out by screen readers. On Android, show the message in a view with `accessibilityLiveRegion="polite"`: Android 16 deprecated announcements. On iOS, announce it with `AccessibilityInfo.announceForAccessibility`.
- Check every UI change on both iOS and Android; behavior differs (keyboard, insets, fonts, permissions).
- Give every interactive element a `testID` (kebab-case, for example `dark-mode-switch`). End-to-end tools tap by `testID`. On iOS, React Native exposes a label and its control as duplicate accessibility elements, so tapping by text can hit the label: nothing happens, yet the tool reports success.
- Give every interactive element an `accessibilityLabel` that says what it does and an `accessibilityRole` (`button`, `link`, `switch`, …), so screen readers can use it. Icon-only buttons need it most; screen readers don't read `testID`.

## Tablets and landscape

`AGENTS.md` lists the screens this app supports: phones and tablets, portrait and landscape. Build every screen for each of them, and skip what isn't listed. `verify.sh` checks each one.

- One set of screens for every device: layouts adapt to the window. No separate tablet copies of screens, and no phone-width column centered on a tablet.
- Read the window size with `useWindowDimensions()`, which updates on rotation, split view and resizable windows. `Dimensions.get` read once at startup goes stale.
- Lay out by window width: under 600 points (dp on Android), the phone layout; from 600, the tablet layout, with more columns, and a list beside its detail where that helps. Text-heavy content and forms keep a readable width (about 600 to 700 points) instead of stretching edge to edge.
- Sizes: when the app already has a way to size things (a scaling helper, or sizes in its theme), use it everywhere and don't mix in another. A new app takes sizes from its theme: spacing and a few text sizes step up from 600 points, and text follows the system font size. Judge the tablet and landscape screenshots like the phone's: each should look made for that screen, not stretched or tiny.
- Landscape leaves little height: screens scroll, the keyboard covers more, and the safe-area insets include the left and right edges (the notch or Dynamic Island side).
- Android ignores orientation and size locks on tablets and foldables (600 dp wide and up) for apps targeting Android 16 (API 36), and from Android 17 (API 37) apps can't opt out. Apple deprecated `UIRequiresFullScreen` with iPadOS 26, so iPad windows resize too, and on iOS 27 `ScreenOrientation.lockAsync` may do nothing. Every screen has to work at any window size and turned, whatever the app's settings say.
- Don't lock the orientation in code to avoid layout work. Which orientations the app supports is a product decision, set in `app.json`: `orientation` (`default` turns, `portrait` or `landscape` locks) and `ios.supportsTablet` for the iPad app.

## Current Expo, React Native and React

These changed after most AI training data was written: check them instead of writing from memory.

- Navigation (SDK 56 and later): import from Expo Router's own entry points, such as `expo-router/react-navigation`, never from `@react-navigation/*`, which no longer works alongside it (`expo-router` skill; the `expo-upgrade` skill's codemod moves old imports).
- `expo-av` isn't maintained any more: use `expo-audio` and `expo-video`. `@expo/vector-icons` is deprecated from SDK 56: use `@react-native-vector-icons/*`. In `expo-file-system`, `File` and `Directory`'s `copy` and `move` (SDK 56) and `File.write` (SDK 58) are async; the `…Sync` versions aren't.
- iOS: from SDK 58, prebuild generates `SceneDelegate.swift`, as apps built with Xcode 27 don't launch without the UIScene life cycle. Config plugins that change the app delegate's window or URL handling have to change the scene delegate instead.
- Removed from React Native: `InteractionManager` (0.87; use `requestIdleCallback`), the `StatusBar` props `backgroundColor` and `translucent` (0.87), `Modal`'s `animated` (0.87; `animationType`), a boolean `keyboardShouldPersistTaps` (0.87; `"handled"`) and `StyleSheet.absoluteFillObject` (0.85; `StyleSheet.absoluteFill`).
- Deprecated, so not in new code: `ImageBackground` (a `View` with an absolutely positioned image), `InputAccessoryView` (`KeyboardStickyView` from `react-native-keyboard-controller`) and `AccessibilityInfo.setAccessibilityFocus` (`sendAccessibilityEvent`).
- Import from `react-native` itself. `react-native/Libraries/…` is private, and a type error from React Native 0.87; don't add the `react-native-legacy-deep-imports` opt-out to hide it.
- React 19: pass `ref` as a prop instead of `forwardRef`, render `<SomeContext value={…}>` instead of `<SomeContext.Provider>`, and use `useEffectEvent` (19.2) instead of turning off `react-hooks/exhaustive-deps`.
- With the React Compiler on (`experiments.reactCompiler` in `app.json`), it memoizes: don't add `memo`, `useMemo` or `useCallback` to new code, and don't remove the ones there as a side task.
- Android: Google Play takes only apps targeting Android 16 (API 36) or higher (from 31 August 2026). Don't lower the target SDK to get out of edge to edge, back handling or orientation changes.

## Errors, storage and effects

- Wrap the app in an error boundary, so a render error shows a screen to recover from instead of a blank or closed app: export an `ErrorBoundary` from the root layout (Expo Router), or use the crash reporter's.
- Every failure reaches the user or the crash reporter: no empty `catch`, and an action started from a button catches its error and shows it, with a way to retry, so a spinner never stays up.
- Tokens, passwords and keys go in `expo-secure-store`, never in AsyncStorage or other plain storage. Anything in the JavaScript bundle, `EXPO_PUBLIC_` variables included, can be read by anyone who has the app: no secret keys there.
- Session replay and analytics mask what users type, and logs leave out tokens and personal data.
- Effects clean up what they start: timers (`clearTimeout`, `clearInterval`), listeners and subscriptions (return their `remove`), and async work that can finish after the screen closes (an `AbortController`, or a flag the cleanup sets).
- List keys come from the item's ID, not its index: index keys mix up rows when items are added, removed or reordered.
- Images go in asset files, never in code as base64 strings: they bloat the bundle, and all of it loads with the JavaScript.
- Component tests use React Native Testing Library (`@testing-library/react-native`) and find elements as users and screen readers do, by role, label or text (`getByRole('button', { name: 'Save' })`), rather than relying on snapshots.
- A test checks what a user or a caller sees, through the public interface (rendered text and roles, a hook's result, a function's return), so a refactor that keeps the behavior keeps the test passing.
- Mock only what the app doesn't own: the network, storage, native modules, time and randomness. Not the app's own components, hooks or modules: a test of mocks passes whatever the code does.
- Expected values come from the spec or a worked example (`expect(total([10, 5])).toBe(15)`), never computed the way the code computes them, or the test can't fail.
- A bug fix comes with a test that failed before the fix.

## Platform guidelines and accessibility

From Apple's Human Interface Guidelines, Android's design and app quality guidelines, and WCAG 2.2.

- Touch targets: every button, link and control is at least 44×44 points on iOS and 48×48 dp on Android (`minWidth`/`minHeight: 48` covers both): pad a small icon instead of sizing the button to it. `hitSlop` doesn't reach past the parent's bounds, so use it only where the layout can't grow.
- Text: no `fontSize` under 11, and don't cap scaling below 2× (`maxFontSizeMultiplier`, or `Text.defaultProps`).
- Contrast, in both light and dark: text 4.5:1 against its background (3:1 from 18 points, or 14 bold), and input borders, focus rings and icons that carry meaning 3:1. Colors come from the theme, whose pairs are checked once; a grey like `#999` on white is only 2.8:1.
- Screen readers: controls show their state in `accessibilityState` (`checked`, `selected`, `expanded`, `disabled`), and screen and section titles have `accessibilityRole="header"`. A label names the action ("Delete photo"), without the role ("button") the reader already says. Put `accessible` on a row that reads as one item, never on one that holds its own buttons. Meaningful images get a label; decorative ones need nothing.
- Every swipe, drag or long-press action also has a visible button or menu item, and is in `accessibilityActions`. Color is never the only signal: an error shows text, and a state adds an icon or a word.
- Back: keep swipe back on iOS and the system back on Android. To ask before leaving unsaved changes, use `usePreventRemove` (from `expo-router/react-navigation`), not `gestureEnabled: false`. A `hardwareBackPress` listener returns `true` only while it closes something on screen; apps don't quit themselves (`BackHandler.exitApp`). Every `Modal` has `onRequestClose`, which Android's back button calls; forms open as sheets (a route with `presentation: 'formSheet'`, or `presentationStyle="pageSheet"`).
- Permissions: ask when the user starts the feature that needs it, never at launch or when a screen opens; first say in the app why. When it's denied, say what's unavailable and keep the rest working. When the system won't ask again (`canAskAgain` is false), the feature's button explains that and offers `Linking.openSettings()`. Ask for notifications after an action they serve, not on launch; on Android 13 and later, `expo-notifications` shows the prompt only once a notification channel exists, so create it first.
- Use the native controls (`@react-native-community/datetimepicker`, `Alert.alert` with verb buttons and `style: 'destructive'` and `'cancel'`, `Switch`); a custom one gets the same role, state and size.
- Dark mode: `userInterfaceStyle: "automatic"` in `app.json` (Android also needs `expo-system-ui`), and colors from the theme's light and dark values (`useColorScheme()`), not hex values in components; don't lock the app to light.
- Data screens have loading, empty (why, and what to do next), error (what failed, with Retry) and content states. A message the user has to read doesn't vanish on a timer, and screen readers announce it.
- Nothing on a screen is invented: texts, numbers, ratings, reviews, user counts and images come from the spec, the app's data or the client. Where one is missing, a placeholder the PR lists (and `specs/<id>/questions-<who>.md` asks for), never a made-up figure, quote or rating. Brand colours, fonts and logos come from the project or the client, never from memory. A prototype's mock data stays in its mock-data file.
- Texts say what things do, in the app's words (`docs/amk/glossary.md`), not marketing filler (seamless, effortless, unlock your potential); icons come from the app's icon set, not emoji.
- Reduce Motion: with it on, nothing loops or moves for decoration. Don't pass `ReduceMotion.Never` to Reanimated for decoration; with `Animated` or Lottie, read `AccessibilityInfo.isReduceMotionEnabled()` and the `reduceMotionChanged` event, and fade or stop instead.
- iOS 26: use native headers and tab bars (Expo Router's `Stack` and native tabs), which iOS draws in its current style; don't draw imitation glass behind content, or opt out with `UIDesignRequiresCompatibility` (builds with the iOS 27 SDK ignore it). Nothing the user needs sits under a floating tab bar, button or footer: scroll content gets bottom padding for it.
- Haptics only for success, error or a selection, never as the only feedback, with `expo-haptics`; not `Vibration.vibrate`.

## Store review

What App Store review and Google Play reject. `node scripts/amk/release-check.js` checks the app config for some of it.

- Apps where people can create an account let them start deleting it in the app: a full deletion, not deactivation; a direct link to a web page that finishes it is fine (Apple 5.1.1(v)). Google Play also needs that web link in the Data safety form.
- A third-party or social login (Google, Facebook) as the main sign-in also needs an equivalent private one, usually Sign in with Apple (`expo-apple-authentication`, 4.8); an app that signs in only with the company's own accounts doesn't.
- Digital content and subscriptions are sold with in-app purchase (3.1.1); physical goods and services aren't. Links to buy elsewhere follow the storefront's current rules.
- Permission texts (in each library's plugin options, or `ios.infoPlist`) say what the app does with the data and why, for each use; ask only for what the app uses.
- The privacy manifest (`ios.privacyManifests` in `app.json`) and App Store Connect's privacy details list the data the app and its SDKs collect (analytics, crash reporting, session replay). Tracking needs the App Tracking Transparency prompt first (`expo-tracking-transparency`).
- Google Play restricts these permissions to apps whose core feature needs them, with a declaration in Play Console: photos and videos (`READ_MEDIA_IMAGES`, `READ_MEDIA_VIDEO`: others use the Android photo picker), `QUERY_ALL_PACKAGES`, `MANAGE_EXTERNAL_STORAGE`, SMS and call log, `USE_EXACT_ALARM`, and background location (also a video and an in-app disclosure first). A library can add one: list it in `android.blockedPermissions` when the app doesn't need it.
- Android foreground services declare their type and its `FOREGROUND_SERVICE_<TYPE>` permission (the library's config plugin usually does), and each type is declared in Play Console.

## TypeScript

- Keep the checks `tsconfig.json` has. Don't loosen them, or get past one with `any`, `@ts-ignore` or a non-null `!`.
- New apps from `init --new` also turn on `noUncheckedIndexedAccess`, `noImplicitOverride`, `noImplicitReturns` and `noFallthroughCasesInSwitch`. In an existing app, turning these on is a change of its own (`m-change`), since they flag code that already exists.
- Import with the app's path alias when `tsconfig.json` has one (`@/` for `src/` in new apps) instead of long relative paths. Expo's Metro reads the alias from `tsconfig.json` by itself.

## Performance and libraries

- Prefer Expo's own modules (`expo-image`, `expo-file-system`, `expo-secure-store`, …) when one fits.
- Follow the `react-native-best-practices` skill for lists, re-renders, startup time and bundle size.
