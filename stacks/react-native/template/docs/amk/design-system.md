# Design system

<!-- How the app looks, so every new screen matches the ones it has. Facts from the app's theme and shared components,
each with the file it comes from, not advice. m-onboard drafts it; something new (a colour, a component) is added here
and to the theme before a screen uses it.
- Theme: the file(s) holding colours, type and spacing (`src/theme/…`), and how a screen reads them (a hook, an import).
- Colours, by role: background, surface (cards, sheets), text, muted text, primary (the main action), error, success,
  border. Dark mode's too, if the app has it.
- Type: the font(s), and the size and weight of each role in use (title, heading, body, caption, button).
- Spacing and shape: the spacing steps (4, 8, 16, …), corner radius, shadows.
- Controls: the primary and secondary button, text field, list row, and the shared components that draw them.
- Icons: the set (library) and its sizes; images and illustrations, if the app has them.
- Motion: what animates and for how long, and what happens with Reduce Motion on.
- Voice: how the app's texts speak (formal or casual, "you") and the words its buttons use (Save, Done, …).
